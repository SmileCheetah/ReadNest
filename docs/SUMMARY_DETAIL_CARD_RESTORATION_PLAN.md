# 요약 상세 카드 복원 계획

## 목표

단일 `summaryMarkdown` 문서 구조는 유지하면서, 상세 화면의 요약 영역을 기존 Unwind의 브랜드가 드러나는 하나의 `AI 요약` 카드로 복원한다. V1 요약, 별도 3개 핵심 포인트, 중복된 자세한 요약 영역은 다시 만들지 않는다.

## 현재 문제

- Markdown 제목과 본문이 페이지에 바로 이어져 요약 영역의 시작과 끝이 불분명하다.
- 요약 완료 전후의 화면 골격이 달라 보여 화면이 다른 디자인으로 교체된 것처럼 느껴진다.
- 원문 보기와 복사 액션이 같은 행에 있어 Primary CTA의 우선순위가 약하다.
- 데이터 계약을 하나로 통일하는 작업이 시각적 표면까지 제거하는 결과로 이어졌다.

| 요약 상태마다 레이아웃이 달라짐 | 상태별 별도 UI / 동일한 표면 | 같은 카드 안에서 상태만 변경 | 로딩·실패·완료 전환 시 화면 점프와 이질감 감소 | 상태 카드 전용 장식은 사용하지 않음 |

## 화면 구조

1. 저장 출처와 날짜
2. 글 제목
3. 오류·원문 일부 누락 등 필요한 안내
4. 단일 `AI 요약` 카드
   - AI 요약 헤더와 복사 액션
   - 전체 Markdown 요약 문서
   - 도입부 다음의 `원문 보기` Primary CTA
   - 긴 문서의 `전체 요약 펼치기`
5. 태그와 원문 수집 정보

상세 화면에서 다른 글로 이동하면 이전 글의 스크롤 위치를 이어받지 않고 문서 시작점으로 이동한다.

## 데이터 및 Backend 영향

- API와 DB 변경 없음
- `summaryMeta.summaryMarkdown`만 사용
- 요약 프롬프트, Luna 모델, 요약 길이 정책 변경 없음
- V1/V2 렌더링 분기 추가 없음

## 접근성 기준

- 제목과 Markdown heading의 읽기 순서를 유지한다.
- 복사와 원문 보기의 터치 영역은 최소 44×44px로 유지한다.
- 복사 성공·실패의 스크린리더 알림을 유지한다.
- 320px 폭에서 가로 스크롤이 생기지 않게 한다.
- 200% 글자 확대에서도 고정 높이로 내용을 자르지 않는다.
- 카드 안에 카드를 중첩하지 않는다.

## 테스트 계획

- `npm run typecheck`
- `npm test -- --runInBand`
- `git diff --check`
- 합성 API를 사용하는 Expo Web 시각 회귀 검사
  - 390px 상세 화면
  - 320px 상세 화면과 가로 overflow
  - 긴 문서 접기/펼치기
  - 화면 제목 1회 표시
- 실제 Android의 200% 글자 확대와 TalkBack은 기기에서 최종 확인

## 완료 조건

- 완료·로딩·실패 상태가 모두 같은 `AI 요약` 카드 골격을 사용한다.
- Markdown 전체 내용과 순서가 유지된다.
- 화면에 제목이 한 번만 표시된다.
- 별도 핵심 포인트 또는 자세한 요약이 중복 표시되지 않는다.
- 원문 보기가 유일한 Primary CTA다.
- 자동 검사와 시각 회귀 검사가 통과한다.

## 구현 및 검증 결과

- 완료·로딩·실패 상태에 동일한 단일 카드 골격 적용
- Markdown H1은 카드 밖의 화면 제목으로 한 번만 표시
- 복사 액션은 `AI 요약` 헤더로, 원문 보기는 전체 폭 Primary CTA로 분리
- 글 전환 시 상세 화면 스크롤을 문서 시작점으로 초기화
- 390px 및 320px Expo Web 렌더링 확인
- 320px 가로 overflow 없음
- 긴 문서의 순차 접기/펼치기 확인
- `npm run typecheck` 통과
- `npm test -- --runInBand`: 6 suites / 61 tests 통과
- `git diff --check` 통과
- 실제 Android 200% 글자 확대와 TalkBack은 기기 검증 대상으로 유지

## 이번 범위에서 제외

요약을 더 짧게 또는 더 길게 다시 생성하는 밀도 조절 기능은 별도 제품 결정이 필요한 후속 작업이다. 이번 변경에는 UI 자리나 API 호출을 미리 추가하지 않는다.
