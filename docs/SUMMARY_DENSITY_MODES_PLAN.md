# 요약 밀도 선택 기능 계획

## 목표

사용자가 같은 저장글을 읽는 목적에 따라 `핵심만`, `기본`, `자세히` 중 하나를 선택할 수 있게 한다. 밀도는 핵심 항목의 개수를 기계적으로 줄이거나 늘리는 기능이 아니라, 원문의 독립적인 주장과 구조를 보존한 채 각 항목의 설명 깊이를 조절하는 기능이다.

## 사용자 경험

- 최초 화면은 기존 `기본` 요약을 즉시 표시한다.
- `핵심만`과 `자세히`는 사용자가 처음 선택할 때만 생성한다.
- 생성 중에는 현재 읽던 요약을 지우거나 로딩 화면으로 대체하지 않는다.
- 생성에 성공하면 선택한 밀도로 자동 전환하고, 이후에는 저장된 결과를 즉시 표시한다.
- 생성에 실패하면 현재 요약을 유지하고 해당 밀도만 재시도할 수 있게 한다.
- 기본 요약을 다시 생성하면 이전 원문 세대에서 만든 대체 밀도는 사용하지 않는다.
- 일부 원문만 수집된 글은 `자세히`에서도 수집된 범위 밖의 내용을 복원할 수 없음을 안내한다.

## 밀도 의미

| 밀도 | 목적 | 생성 원칙 |
| --- | --- | --- |
| 핵심만 | 저장 이유와 기억할 내용을 빠르게 회상 | 독립적인 주장·단계·조건은 유지하고 설명과 사례를 강하게 압축 |
| 기본 | 내용을 짧게 이해 | 현재 요약 규칙을 그대로 사용 |
| 자세히 | 논리와 맥락까지 확인 | 같은 수집 원문에서 근거·비교·조건·예외·중요 사례를 더 보존 |

고정 항목 수는 두지 않는다. 모든 밀도는 이미 생성된 요약이 아니라 같은 `rawText` 원문을 입력으로 사용한다.

## 선택한 구조

### 기본 요약 유지

기존 `SavedArticle.summaryMeta.summaryMarkdown`과 기본 요약 작업 큐는 변경하지 않는다. 기본 요약의 성공·실패 상태가 앱 전체에서 이미 사용되고 있으므로, 대체 밀도의 상태와 섞지 않는다.

### 대체 밀도 격리

`SummaryVariant`와 `SummaryVariantTask`를 추가한다.

- `SummaryVariant`: 글·밀도별 최신 Markdown과 생성 상태를 저장한다.
- `SummaryVariantTask`: Redis 전달 실패와 worker 중단에도 복구할 수 있는 durable outbox다.
- 결과에는 생성에 사용한 기본 요약의 `resultGeneration`을 기록한다.
- 현재 글의 `resultGeneration`과 다른 결과는 stale로 간주해 API와 화면에서 사용하지 않는다.
- 글 삭제 시 variant와 task도 cascade 삭제한다.

대체 밀도 작업은 별도 BullMQ queue와 worker를 사용한다. 대체 밀도 실패가 `SavedArticle.processStatus`를 변경하거나 정상 기본 요약을 실패 상태로 만들지 않는다.

## API 계약

- `GET /api/articles/:articleId`
  - 현재 원문 세대와 일치하는 `summaryVariants`를 함께 반환한다.
- `GET /api/articles/:articleId/summary/variants`
  - 대체 밀도 상태를 다시 조회한다.
- `POST /api/articles/:articleId/summary/variants/:density`
  - `concise` 또는 `detailed` 생성을 요청한다.
  - 성공 결과가 이미 있거나 같은 작업이 진행 중이면 새 AI 호출을 만들지 않는다.
  - `Idempotency-Key`를 지원한다.

공개 상태는 `PENDING`, `RUNNING`, `SUCCEEDED`, `FAILED`이며 실패에는 사용자용 오류 코드, 재시도 가능 여부와 재시도 대기 시간을 포함한다. 내부 오류 원문은 노출하지 않는다.

## 프롬프트 전략

현재 기본 프롬프트와 모델은 유지한다. 대체 밀도 호출에만 짧은 밀도 지침을 추가한다.

- 모든 밀도에서 독립적인 주장·조건·비교·중요 수치를 보존한다.
- `핵심만`은 항목 수를 임의로 제한하지 않고 설명을 압축한다.
- `자세히`는 기본 요약을 늘리지 않고 원문에서 다시 생성한다.
- 수집되지 않은 맥락을 추측하지 않는다.
- 같은 의미의 반복으로 길이만 늘리지 않는다.

## 화면 설계

`AI 요약` 헤더 아래에 3분할 선택기를 둔다.

- 순서: `핵심만 · 기본 · 자세히`
- 선택 영역은 각각 최소 44px이며 선택 상태를 스크린리더에 전달한다.
- 새 카드나 중첩 surface를 만들지 않고 기존 요약 카드 안에서 hairline과 옅은 배경만 사용한다.
- 생성 중에는 선택한 버튼에 진행 상태를 표시하고, 아래에 “현재 기본 요약을 표시하고 있어요”처럼 현재 상태를 설명한다.
- 실패 시 현재 문서를 유지하면서 인라인 `다시 시도`를 제공한다.
- 복사와 공유는 화면에 실제로 표시 중인 밀도의 전체 Markdown을 사용한다.
- 320px 폭과 200% 글자 크기에서도 고정 높이로 내용을 자르지 않는다.

## 동시성·비용·복구

- `(articleId, density)`당 한 개의 최신 variant만 유지한다.
- `(variantId, generation)`을 작업의 낙관적 세대로 사용해 오래된 worker가 새 결과를 덮어쓰지 못하게 한다.
- 성공한 현재 세대 결과는 캐시처럼 재사용하며 다시 호출하지 않는다.
- lease heartbeat, 최대 자동 시도 횟수, 지수 backoff를 적용한다.
- 네트워크 요청이 끊겨도 DB outbox가 남아 재전달된다.
- 원문이 없거나 기본 요약이 아직 완료되지 않은 경우 대체 밀도를 시작하지 않는다.

## 테스트 계획

### Backend

- 기본/핵심만/자세히 프롬프트 차이와 항목 수 강제 금지
- 모든 모드가 제공된 원문을 직접 사용하는지 확인
- 성공 결과 캐시 및 진행 중 중복 요청 방지
- 소유권 검사와 잘못된 density 거부
- base generation 변경 시 stale variant 미노출
- worker lease, 자동 재시도, 오래된 결과 덮어쓰기 방지
- variant 실패가 기본 `processStatus`를 변경하지 않음
- migration과 Prisma Client 생성, build, 전체 테스트

### Frontend

- 기본이 최초 선택되고 즉시 표시됨
- 캐시된 밀도는 AI 요청 없이 전환됨
- 미생성 밀도 선택 시 현재 문서를 유지함
- 완료 후 선택 문서로 자동 전환됨
- 실패 후 현재 문서 유지 및 재시도
- 부분 원문 + 자세히 안내
- 복사·공유가 현재 표시 문서를 사용함
- 320px 폭, 200% font scale, TalkBack/VoiceOver 선택 상태
- typecheck, Jest 전체 테스트, 실제 화면 캡처

## 완료 기준

1. 기본 요약 흐름과 기존 저장글이 그대로 동작한다.
2. 대체 밀도는 동일한 수집 원문에서 한 번만 생성되고 저장된다.
3. 생성·실패 중에도 읽던 요약이 사라지지 않는다.
4. 대체 밀도 실패가 글 전체의 요약 실패로 표시되지 않는다.
5. 앱 재시작 후에도 생성 결과와 작업 상태가 유지된다.
6. 자동 테스트와 실제 320px 화면 검증을 통과한다.

## 구현 결과 — 2026-09-30

- 기본 요약 경로를 유지하고 `summary_variants`, `summary_variant_tasks`를 추가했다.
- 대체 밀도 전용 BullMQ queue, lease, heartbeat, 자동 재시도와 Markdown checkpoint를 구현했다.
- `resultGeneration`이 다른 결과는 API와 앱 모두에서 사용하지 않는다.
- Luna 모델과 기본 프롬프트는 그대로 유지하고, `핵심만`과 `자세히` 요청에만 밀도 지침을 덧붙인다.
- 상세 화면에 44px 이상 3분할 선택기를 추가했다. 생성·실패 중에도 기본 문서를 유지하며, 성공한 밀도는 즉시 재사용한다.
- 복사와 공유는 현재 화면에 표시된 밀도의 전체 Markdown을 사용한다.
- 로컬 MySQL에 migration을 적용했다.
- Backend build 및 112개 테스트, Mobile typecheck 및 67개 테스트를 통과했다.
- Expo web 합성 API 검증에서 390px·320px 기본 화면, 320px `핵심만` 전환, 긴 문서 접힘을 확인했고 가로 overflow와 브라우저 오류가 없었다. 증거는 `docs/assets/summary-density-20260930/`에 저장했다.
- 네이티브 200% font scale 및 TalkBack/VoiceOver 실기기 검증은 별도 확인 항목으로 남는다.
