# Threads 연속 글 수집·요약 구현 계획

## 목표

Threads URL 하나를 입력하면 `1/8`부터 `8/8`까지 이어지는 게시물을 순서대로 수집하고, 전체 내용을 바탕으로 문단별 핵심과 통합 요약을 제공한다.

## 처리 흐름

1. 시작 게시물에서 `현재 번호/전체 개수` 패턴을 찾는다.
   - `1/8`, `1 / 8`, `1／8` 형식을 허용한다.
   - 번호가 없으면 단일 게시물로 처리한다.
2. 같은 작성자의 후속 게시물을 탐색한다.
   - 페이지 DOM의 연속 게시물
   - 동일 작성자의 답글
   - 후속 게시물 링크
   순서로 시도한다.
3. 게시물 URL을 기준으로 중복을 제거하고 번호 오름차순으로 정렬한다.
4. `현재 번호 === 전체 개수`에 도달하면 `COMPLETE`로 표시한다.
5. 다음 게시물을 찾지 못하거나 로그인 벽·타임아웃을 만나면 수집한 내용만 저장하고 `PARTIAL` 또는 `CONTEXT_INSUFFICIENT`로 표시한다.
6. 각 게시물과 문단을 먼저 요약한 뒤, 하위 요약을 통합하여 전체 스레드 요약을 생성한다.

## 저장 모델 방향

현재의 `ThreadGroup`과 `ThreadPart` 구조를 활용한다.

```ts
type ThreadCollection = {
  currentPart: number;
  totalParts: number;
  collectedParts: number;
  status: 'PARTIAL' | 'COMPLETE';
};
```

각 파트에는 번호, 원문 URL, 작성자, 원문 텍스트, 추출 상태를 저장한다. 사용자별 원문·요약 데이터는 계정 삭제 요청 시 함께 삭제한다.

## 요약 결과

최종 결과는 다음 정보를 포함한다.

- 제목
- 한 줄 요약
- 전체 맥락 요약
- 파트 또는 문단별 핵심 내용
- 핵심 포인트
- 태그
- 수집 상태와 `수집 파트 수/전체 파트 수`
- 요약 신뢰도 및 누락 경고

긴 스레드는 `파트별 요약 → 통합 요약`의 2단계 방식으로 처리하여 입력 길이와 누락 위험을 줄인다.

## 구현 순서

1. 번호 패턴 파서와 단위 테스트 작성
2. 후속 게시물 탐색 및 작성자 검증
3. 중복 제거·순서 정렬·종료 조건 구현
4. 부분 수집 상태와 누락 경고 저장
5. 파트별·문단별 핵심 추출
6. 전체 스레드 통합 요약 프롬프트 구현
7. 상세 화면에 수집 상태와 누락 여부 표시
8. 실제 `1/8 → 8/8` 링크로 통합 테스트

## 완료 기준

- `1/8` 링크에서 `8/8`까지 수집된다.
- 같은 작성자의 게시물만 연결된다.
- 게시물 순서가 보존된다.
- 중복 게시물이 한 번만 저장된다.
- 일부 게시물 누락 시 완료로 표시하지 않는다.
- 최종 요약에 전체 흐름과 각 파트의 핵심이 반영된다.
