# Threads 지식 Wiki 개선 계획

저장한 Threads를 읽고 끝내는 보관함에서, 출처를 확인하며 지식을 연결하고 다시 활용하는 개인 지식 서비스로 확장한다. 원문, AI 요약, 사용자의 메모, 여러 출처를 종합한 Wiki는 구분한다. Obsidian의 연결형 노트 경험을 참고하되 특정 외부 저장소와 자동 동기화하는 것으로 해석하지 않는다.

## 이번 적용 범위

2026-10-07 기준 모델 전환과 출처 노트 복사에 이어 **수동 주제 기능과 원문 근거 기반 자동 글 연결**을 구현했다. 앱 내부 Wiki 편집기, 완전한 자유 배치 그래프, 자동 종합, 저장 글 기반 질문은 아직 구현하지 않았다. 후속 [구현 명세](KNOWLEDGE_WIKI_IMPLEMENTATION_SPEC.md)에 완료 범위와 다음 단계의 데이터, API, 화면, 삭제 정책을 구분한다.

- 기본 모델과 `.env.example`, 현재 로컬 서버 `.env`의 `OPENAI_MODEL`을 `gpt-6-luna`로 변경했다. 모바일 `.env.local`에 남아 있던 동일 모델 설정도 맞췄으나 실제 요약은 서버에서 실행된다. 비밀 환경 파일은 커밋하지 않는다.
- Responses API, 기존 요약 프롬프트, 세 가지 밀도, 오류 처리 및 저장 계약은 유지했다. 환경변수로 명시한 다른 모델은 존중하고 빈 설정은 기본 모델을 사용한다.
- 상세 화면의 더보기 메뉴에 **Obsidian 노트 복사**를 추가했다. 기존 읽기 디자인과 일반 복사·공유 동작은 유지한다.
- 현재 표시된 요약 전체, 원문 HTTPS 링크, 저장 시각, 요약 생성 시각(존재할 때), 밀도, 문서 ID, 원문 수집 상태를 Markdown과 YAML 속성으로 복사한다. 추가 AI 호출이나 자동 파일 쓰기는 하지 않는다.
- AI 요약과 원문 완전성 경고를 남기고, 사용자가 직접 작성할 빈 ‘내 메모’ 영역을 제공한다. 수집 완전성이 UNKNOWN이면 완전 수집으로 표현하지 않는다.
- 제목 등 메타데이터는 인용 처리하며 위험 URL scheme·인증정보가 포함된 링크는 내보내지 않는다. 본문을 다시 요약하거나 연결·태그·모델 이력을 지어내지 않는다.

사용법: 글 상세 → 더보기 → Obsidian 노트 복사 → Obsidian의 빈 Markdown 노트에 붙여넣기. 기존 노트 중간에 붙이면 YAML 속성이 문서 속성으로 적용되지 않을 수 있다. Vault 자동 저장·동기화 기능은 아니다.

### 주제별로 글 모으기

- 보관함 → **주제로 모아보기**에서 주제를 만들고 이름·설명을 편집한다. 저장글을 검색해 여러 개 선택하거나 글 상세 → 더보기 → **주제에 추가**에서 여러 주제에 연결한다.
- 주제와 연결은 서버에 저장하며 AI 요약 태그와 분리한다. 주제 선택·조회는 AI 호출이나 읽음 처리를 만들지 않는다. 실제 요약 상세 진입 시에는 기존 읽음 정책을 적용한다.
- 주제 안에서 글을 읽고 돌아와도 주제 화면을 유지하고 글 수·연결 목록을 갱신한다. 연결 해제나 주제 삭제는 저장글과 요약을 삭제하지 않는다.
- 입력·선택을 저장하지 않고 나갈 때 확인을 제공한다. 일부 연결 실패는 실패한 선택을 남겨 재시도하며, 수정 충돌은 입력을 보존하고 서버의 최신 내용과 비교할 수 있게 한다.
- 기존 요약 문서 디자인·프롬프트·밀도 조절을 변경하지 않는다. 기존 파란색 토큰과 문서형 디자인을 유지하며 새로운 주제 화면에만 목록·입력·선택 상태를 추가했다.

### 자동으로 이어지는 글

- 보관함의 기본 진입은 **이어지는 생각 보기**다. 주제 이름을 짓거나 글을 수동으로 넣을 필요가 없다. 이전에 만든 수동 주제는 **내가 만든 주제 보기**에서 그대로 이용한다.
- 요약을 저장한 뒤 자동 연결 작업을 별도 큐에 넣는다. 기존 글은 연결 화면을 열 때 한 번에 최대 5개씩 백그라운드 탐색한다. 연결 실패는 요약 성공 상태를 바꾸지 않고 화면에서 글별 재시도를 제공한다.
- 같은 계정의 최근 저장글 중 원문 단어가 겹치는 후보를 우선 제시하되, AI가 실제로 의미 있는 보완·유사·대조 관계가 없으면 연결하지 않는다. 최대 3개를 저장한다. AI가 제시한 양쪽 근거 문구가 각각 저장 원문의 정확한 부분 문자열일 때만 연결을 수락한다. 근거 검증은 인용 존재 여부이지 관계의 진실성을 완전히 증명하지는 않는다.
- 연결은 양쪽 글의 요약 generation과 함께 저장한다. 재요약으로 원문 스냅샷이 바뀌면 오래된 연결은 조회에서 숨기고 새 연결을 찾는다. 글을 삭제하면 해당 연결·탐색 기록도 DB FK cascade로 제거된다.
- 화면은 최근 80개 글의 연결과 양쪽 원문 근거를 보여준다. 선으로 이어지는 애니메이션은 약하게 적용하고 운영체제의 동작 줄이기 설정을 따른다. 이것은 자유 배치 지식 그래프나 AI 종합 Wiki 문서가 아니다.
- 비용 상한: 새 원문당 연결 모델 호출 최대 1회, 후보 최대 8개·출력 연결 최대 3개. 후보가 없으면 모델을 호출하지 않는다. 기존 글은 화면이 열린 동안 8초마다 최대 5개씩 순차적으로 대기열에 넣는다. 오래된 글이 많은 계정은 백그라운드 호출 비용과 탐색 시간이 늘 수 있으므로 운영 전 일일 계정별 예산과 동시성 제한을 추가 검토한다.

## 공통 품질 기준

- 사용자별 데이터 격리, 출처 권한 검사, 삭제 시 참조 처리 정책을 마련한다.
- 원문 안의 명령은 자료로 취급하고 모델의 실행 지시로 사용하지 않는다.
- AI 종합 내용과 사용자 작성 내용을 분리하고 출처 없는 단정을 막는다.
- 기존 저장 글·요약은 모델 변경만으로 자동 재생성하지 않는다. 재요약이나 미생성 밀도 생성부터 새 모델을 적용한다.
- Wiki 자동 생성은 원문 수집·기본 요약 완료를 지연시키지 않는 별도 사용자 요청으로 시작한다. 캐시·중복 방지·호출량 제한을 함께 설계한다.
- [요약 지연 우선 개선 계획](SUMMARY_LATENCY_INVESTIGATION.md)의 P1은 유지한다. 기능 추가를 속도 개선 완료로 간주하지 않는다.

## 검증 기록

### 수동 주제 기능

- Backend 전체 **17 suites / 146 tests**, build 통과. 변경한 Backend TypeScript 파일의 eslint 통과.
- Frontend 전체 **12 suites / 98 tests**, typecheck 통과. 늦은 응답·계정 전환·부분 실패·중복 저장·409 충돌·미저장 입력·번호/요약 렌더링 회귀를 포함한다.
- 실제 로컬 MySQL·HTTP 통합 검증 **13/13 통과**. Unicode 경계, 타인 주제/글 접근 거부, 서명 cursor 범위, 동시 중복 연결, revision, 삭제 정책을 검사했다. 합성 사용자 2명과 해당 자료는 실행 후 모두 정리했다. 이 검증의 인증 guard는 테스트 신원이며 실제 JWT 로그인 검증을 대신하지 않는다.
- 실제 Expo Web UI에 합성 API를 연결해 320/390px에서 생성·연결·해제·편집 충돌·미저장 이동 확인·삭제·재시도·상세 복귀를 검사했다. 테스트 스크립트는 `readnest-mobile/scripts/verify-knowledge-ux.mjs`, 캡처는 `/tmp/readnest-knowledge-ux/`다. 선택만으로 읽음 PATCH나 요약 요청이 발생하지 않는 것도 검사했다.
- 기존 `verify-ux.mjs`의 요약 밀도·복사 메뉴·긴 문서 접기/펼치기 회귀 검증도 통과했다. UI 검증은 실제 백엔드와 연결한 통합 테스트가 아니라 합성 API 화면 검증이다.
- StyleSeed build/review 기준으로 기존 토큰, 최소 44px 액션, 제목·본문 계층, 웹 checkbox의 `aria-checked`를 확인했다. 늦은 주제 새로고침이 최신 revision을 덮어쓰지 않고 숨겨진 상세로 포커스를 돌리지 않게 수정했다. 임의 디자인 점수는 부여하지 않는다.
- 320px에서 문구 크기를 두 배로 늘리는 웹 스트레스 검사에서 가로 overflow가 없었다. 실제 기기의 200% font scale·TalkBack/VoiceOver·키보드 동작은 별도 검증이 필요하다. 대규모 보관함 부하와 AI Wiki 품질도 이번 완료 범위가 아니다.
- 모델 요청·요약 프롬프트·기존 저장 요약은 변경하지 않았으며, 요약 지연 P1 과제는 남아 있다.

### 자동 연결 기능

- Backend `npm run build`, 전체 18 suites / 150 tests, 변경 파일 ESLint 통과. 근거가 원문에 없는 연결 거부·다른 후보 ID 거부·중복 제한·후보 선택을 검사했다.
- 실제 `.env`의 설정 모델을 `scripts/smoke-auto-connections.cjs`로 1회 호출했다. 합성 원문 2개에서 구조화 응답 `completed`, 연결 1개, 양쪽 인용의 원문 부분 문자열 검증이 통과했다. 실제 사용자 글의 관계 품질을 증명하는 테스트는 아니다.
- Frontend `npm run typecheck`, 전체 13 suites / 100 tests 통과(새 화면 테스트 2개 포함). 자동 탐색 시작, 양쪽 근거 표시, 주제 생성 강제 없는 빈 상태를 검사했다.
- 로컬 `localhost:3307/readnest`에 migration `20261007010000_auto_connections` 적용. 사용자별 외래키, 연결 쌍 중복 방지, 글 삭제 cascade를 확인했다.
- Expo Web 762px 화면에서 실제 게스트의 빈 상태와 보관함 진입을 확인했다. 실제 저장글 데이터의 AI 연결 품질, 320px/200% 글자 크기와 Android/iOS 동작은 아직 수동 검증이 필요하다.
- StyleSeed 규칙은 `editorial-reading × product-ui × content × detail × editorial-authority × editorial-ink`를 적용했다. 점수 도구가 없어 임의 수치는 기록하지 않는다.

### 이전 모델 전환과 출처 노트

- 공식 [GPT-6 Luna 문서](https://developers.openai.com/api/docs/models/gpt-6-luna)와 [마이그레이션 지침](https://developers.openai.com/api/docs/guides/latest-model/gpt-6-astra.md#migration-quickstart)을 확인했다. 현재 사용하는 Responses 요청에 별도 endpoint 전환은 필요하지 않다.
- 실제 `.env` 키로 새 모델을 1회 호출했다. 지식 관리에 관한 짧은 합성 원문에서 Markdown 검증·정규화까지 성공, 6,483ms. 이전 9.81초 테스트와 입력·측정 범위가 달라 속도 개선 비교에 사용하지 않는다.
- Backend 관련 테스트 35개 및 build 통과.
- Frontend 전체 8 suites / 76 tests, typecheck 통과. 노트 본문 보존·밀도/시각·위험 URL·YAML 인용·실패 재시도·미완성 상태 미노출 포함.

## 실행 환경 반영

로컬 `.env` 모델 값 변경은 서버 프로세스를 재시작해야 확실히 적용된다. 운영 환경은 별도 환경변수 관리 위치에서 `OPENAI_MODEL=gpt-6-luna`를 설정하고 재시작·배포해야 한다. Git 변경만으로 운영 환경변수나 이미 생성된 요약이 바뀌지 않는다.

주제 기능은 새 migration `20261007000000_knowledge_topics`를 적용해야 한다. 기존 글·요약 테이블의 데이터를 변경하지 않고 `knowledge_topics`, `topic_articles` 두 테이블을 추가한다. 로컬 `localhost:3307/readnest`에는 적용했다. 다른 실행 환경에서는 해당 DB를 확인한 뒤 `npm run prisma:generate`, `npm run prisma:migrate:deploy`, `npm run build` 순서로 준비하고 서버를 재시작한다. 프론트도 최신 코드를 다시 불러와야 한다. 운영 DB migration과 배포는 이번 작업에서 실행하지 않았다.

자동 연결에는 추가 migration `20261007010000_auto_connections`가 필요하다. 로컬에는 적용했지만 운영 DB에는 적용하지 않았다. 배포 시 migration·서버 재시작·모바일 번들 갱신이 함께 필요하며, API 키가 없으면 연결 탐색은 실패로 표시되고 요약은 유지된다.
