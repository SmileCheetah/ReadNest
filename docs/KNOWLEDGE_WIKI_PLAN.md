# Threads 지식 Wiki 개선 계획

저장한 Threads를 읽고 끝내는 보관함에서, 출처를 확인하며 지식을 연결하고 다시 활용하는 개인 지식 서비스로 확장한다. 원문, AI 요약, 사용자의 메모, 여러 출처를 종합한 Wiki는 구분한다. Obsidian의 연결형 노트 경험을 참고하되 특정 외부 저장소와 자동 동기화하는 것으로 해석하지 않는다.

## 이번 적용 범위

2026-10-07 기준 첫 단계는 모델 전환과 출처 노트 복사다. 앱 내부 Wiki 편집기, 연결 그래프, 자동 종합, 저장 글 기반 질문은 아직 구현하지 않았다. 우선 기능에 대한 사용자 선택을 요청한 상태다.

- 기본 모델과 `.env.example`, 현재 로컬 서버 `.env`의 `OPENAI_MODEL`을 `gpt-6-luna`로 변경했다. 모바일 `.env.local`에 남아 있던 동일 모델 설정도 맞췄으나 실제 요약은 서버에서 실행된다. 비밀 환경 파일은 커밋하지 않는다.
- Responses API, 기존 요약 프롬프트, 세 가지 밀도, 오류 처리 및 저장 계약은 유지했다. 환경변수로 명시한 다른 모델은 존중하고 빈 설정은 기본 모델을 사용한다.
- 상세 화면의 더보기 메뉴에 **Obsidian 노트 복사**를 추가했다. 기존 읽기 디자인과 일반 복사·공유 동작은 유지한다.
- 현재 표시된 요약 전체, 원문 HTTPS 링크, 저장 시각, 요약 생성 시각(존재할 때), 밀도, 문서 ID, 원문 수집 상태를 Markdown과 YAML 속성으로 복사한다. 추가 AI 호출이나 자동 파일 쓰기는 하지 않는다.
- AI 요약과 원문 완전성 경고를 남기고, 사용자가 직접 작성할 빈 ‘내 메모’ 영역을 제공한다. 수집 완전성이 UNKNOWN이면 완전 수집으로 표현하지 않는다.
- 제목 등 메타데이터는 인용 처리하며 위험 URL scheme·인증정보가 포함된 링크는 내보내지 않는다. 본문을 다시 요약하거나 연결·태그·모델 이력을 지어내지 않는다.

사용법: 글 상세 → 더보기 → Obsidian 노트 복사 → Obsidian의 빈 Markdown 노트에 붙여넣기. 기존 노트 중간에 붙이면 YAML 속성이 문서 속성으로 적용되지 않을 수 있다. Vault 자동 저장·동기화 기능은 아니다.

## 다음 단계 후보

| 단계 | 사용자 가치 | 구현 범위와 안전 기준 |
| --- | --- | --- |
| 주제와 연결 탐색 | 흩어진 글을 다시 찾고 비교 | 사용자가 주제를 편집하고 관련 글을 연결·해제. 자동 추천은 추천 이유를 표시하고 사실 관계나 인과관계로 단정하지 않음 |
| 출처가 있는 Wiki 문서 | 여러 글에서 배운 내용을 한곳에 축적 | 사용자가 선택한 글로 초안 생성, 주장별 내부 출처 링크, 서로 다른 의견·시점 구분, 사용자가 편집·승인 |
| 저장 글 기반 질문 | 저장한 자료를 실제 판단에 활용 | 소유자 권한 안에서 검색, 답변에 근거 글 인용, 근거 부족 안내. 요약뿐 아니라 수집 원문을 사용하고 부분 수집 표시 |
| 변경 이력과 갱신 | 기존 지식의 근거와 수정 내역 추적 | 원문 generation과 문서 참조를 기록, 새 자료 반영은 변경 제안으로 제공. 사용자 메모와 기존 문서를 자동 덮어쓰지 않음 |

추천 순서는 **출처 노트 → 주제·연결 → Wiki 초안 → 근거 기반 질문**이다. 가장 먼저 원하는 사용 경험에 따라 순서를 조정한다. 처음부터 그래프, 임베딩 DB, 모든 글의 자동 재처리를 동시에 도입하지 않는다.

## 공통 품질 기준

- 사용자별 데이터 격리, 출처 권한 검사, 삭제 시 참조 처리 정책을 마련한다.
- 원문 안의 명령은 자료로 취급하고 모델의 실행 지시로 사용하지 않는다.
- AI 종합 내용과 사용자 작성 내용을 분리하고 출처 없는 단정을 막는다.
- 기존 저장 글·요약은 모델 변경만으로 자동 재생성하지 않는다. 재요약이나 미생성 밀도 생성부터 새 모델을 적용한다.
- Wiki 자동 생성은 원문 수집·기본 요약 완료를 지연시키지 않는 별도 사용자 요청으로 시작한다. 캐시·중복 방지·호출량 제한을 함께 설계한다.
- [요약 지연 우선 개선 계획](SUMMARY_LATENCY_INVESTIGATION.md)의 P1은 유지한다. 기능 추가를 속도 개선 완료로 간주하지 않는다.

## 검증 기록

- 공식 [GPT-6 Luna 문서](https://developers.openai.com/api/docs/models/gpt-6-luna)와 [마이그레이션 지침](https://developers.openai.com/api/docs/guides/latest-model/gpt-6-astra.md#migration-quickstart)을 확인했다. 현재 사용하는 Responses 요청에 별도 endpoint 전환은 필요하지 않다.
- 실제 `.env` 키로 새 모델을 1회 호출했다. 지식 관리에 관한 짧은 합성 원문에서 Markdown 검증·정규화까지 성공, 6,483ms. 이전 9.81초 테스트와 입력·측정 범위가 달라 속도 개선 비교에 사용하지 않는다.
- Backend 관련 테스트 35개 및 build 통과.
- Frontend 전체 8 suites / 76 tests, typecheck 통과. 노트 본문 보존·밀도/시각·위험 URL·YAML 인용·실패 재시도·미완성 상태 미노출 포함.
- 기존 디자인 규칙을 유지하고 메뉴에만 보조 액션을 추가했다. StyleSeed code review는 기존 토큰·48px 이상 터치 영역·스크린리더 알림·실패 복구를 확인한다. 수치 점수 도구는 제공되지 않아 임의 점수를 만들지 않는다.
- 실제 Expo Web 화면에 합성 API를 연결한 320/390px 검증 통과. 320px 새 메뉴 및 요약 화면을 캡처·검토했고 터치 영역 44px 이상을 검사했다. 검증 스크립트: `readnest-mobile/scripts/verify-ux.mjs`, 이번 실행 캡처: `/tmp/readnest-knowledge-20261007/`. 실서비스 end-to-end나 실제 Obsidian 연동 검증은 아니다.
- 실제 Obsidian 앱 붙여넣기와 네이티브 200% 글자 크기·TalkBack/VoiceOver는 미검증이다.

## 실행 환경 반영

로컬 `.env` 모델 값 변경은 서버 프로세스를 재시작해야 확실히 적용된다. 운영 환경은 별도 환경변수 관리 위치에서 `OPENAI_MODEL=gpt-6-luna`를 설정하고 재시작·배포해야 한다. Git 변경만으로 운영 환경변수나 이미 생성된 요약이 바뀌지 않는다.
